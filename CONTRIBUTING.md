# Contributing to Foss Explorer

Thank you for your interest in contributing to **Foss Explorer**!

Foss Explorer is an open-source Android browser. Community contributions
help keep it stable, secure, reliable, and compatible with modern
Android versions.

This guide covers contributions to the **current stable 17.x version
only**.

## What We're Looking For

### 1. Bug Fixes

-   Identify and fix existing bugs.
-   Resolve crashes, freezes, and unexpected behavior.
-   Fix UI inconsistencies and broken interactions.
-   Address issues involving bookmarks, history, tabs, and browsing
    functionality.

### 2. Security Improvements

-   Identify potential security vulnerabilities.
-   Fix security-related bugs.
-   Improve existing security mechanisms.
-   Review existing implementations for potential weaknesses.

**Please do not publicly disclose unpatched security vulnerabilities.**
Report them privately to the project maintainer.

### 3. Compatibility Improvements

-   Improve compatibility with newer Android versions.
-   Resolve issues involving different screen sizes and device
    configurations.
-   Address WebView compatibility problems.
-   Fix compatibility issues involving existing browser functionality.

### 4. Performance Improvements

-   Reduce unnecessary resource consumption.
-   Improve application responsiveness.
-   Optimize existing implementations.
-   Address memory leaks and performance regressions.

### 5. Testing and Quality Assurance

-   Test existing functionality across different devices.
-   Identify reproducible bugs.
-   Verify reported fixes.
-   Improve existing automated tests.
-   Report unexpected behavior and compatibility problems.

### 6. Documentation

-   Improve existing documentation.
-   Correct outdated technical information.
-   Clarify existing functionality and configuration.
-   Improve build and testing instructions.

## Contribution Guidelines

Before submitting a contribution:

1.  Check existing issues and pull requests to avoid duplicate work.
2.  Clearly describe the problem you're addressing.
3.  Keep changes focused on the current stable 17.x version.
4.  Avoid unrelated modifications.
5.  Follow the existing project structure and coding conventions.
6.  Test your changes before submitting a pull request.

## Pull Request Requirements

Every pull request should include:

-   A clear and descriptive title.
-   A description of the problem being addressed.
-   An explanation of the changes made.
-   Relevant issue references, if applicable.
-   Testing details and results.

For bug fixes, include steps to reproduce the original problem whenever
possible.

Pull requests may be reviewed, changes may be requested, and submissions
may be accepted or rejected by the project maintainer.

## What Is Outside the Scope?

This contribution initiative is exclusively for maintaining the current
stable 17.x version.

The following are outside its scope:

-   New major features.
-   Major architectural changes.
-   Experimental functionality.
-   Unrelated UI redesigns.
-   Features intended for future major releases.

Contributions should prioritize stability, reliability, security, and
compatibility over introducing additional functionality.

## Code Quality and Testing

Please ensure that:

-   Your changes do not introduce new regressions.
-   Existing functionality remains intact.
-   Relevant tests pass.
-   New functionality is not introduced unnecessarily.
-   Security-sensitive changes receive appropriate attention.

Avoid modifying unrelated code, even when making a small fix.

## Communication

If you're unsure whether a proposed change belongs in the current
maintenance scope, open an issue before starting implementation.

For substantial changes, discuss the proposed solution with the
maintainer first.

Be respectful, constructive, and professional when communicating with
other contributors.

## Final Note

Every contribution matters, whether it's fixing a small bug, improving
compatibility, identifying a security issue, or helping test the
application.

The goal is simple:

**Keep Foss Explorer stable, secure, reliable, and continuously
maintained.**

Thank you for helping maintain Foss Explorer!
